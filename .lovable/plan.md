## Goal

Get literal credentials out of `src/config/app-config.ts` without re-breaking the demo prefill when `.env` is regenerated.

## What changes

**1. `src/config/app-config.ts` — no literal fallbacks**
- `DEMO_EMAIL` / `DEMO_PASSWORD` read only from `import.meta.env.VITE_DEMO_EMAIL` / `VITE_DEMO_PASSWORD`, defaulting to empty string.
- Remove `CREATOR_EMAIL` from the frontend entirely (see step 3).

**2. `src/pages/Auth.tsx` — graceful degradation**
- Prefill the sign-in form only when both demo env vars are present.
- Hide the "demo credentials" hint block and the password-lock behaviour when they're absent, so a missing `.env` degrades to a normal empty login form instead of a broken one.

**3. Creator identity moves server-side only**
- `CREATOR_EMAIL` already exists as an edge-function secret and is enforced in `admin-settings` and `encrypt-existing`. The client keeps using the `is_creator` boolean returned by `admin-settings` (already wired through `useAdminSettings`) instead of comparing emails locally.
- Replace any remaining client-side `CREATOR_EMAIL` comparisons (e.g. in `src/pages/Settings.tsx`) with that `is_creator` flag. This is strictly more secure than today, since the check can't be spoofed by editing the bundle.

**4. `.env` / `.env.example`**
- Re-add `VITE_DEMO_EMAIL` and `VITE_DEMO_PASSWORD` to `.env`.
- Drop `VITE_CREATOR_EMAIL` from `.env.example` and the `ImportMetaEnv` type in `src/vite-env.d.ts`; document that the creator email lives only as a Supabase edge-function secret.

## Important caveat

`.env` is regenerated by the Supabase connection and strips custom keys. When that happens the demo prefill will silently stop working again — but with this change the login page just renders empty instead of breaking, and no credentials sit in source. If you'd rather the prefill never break, the alternative is serving the demo email/password from the `admin-settings` edge function (backed by the `app_settings` table) so it survives `.env` regeneration; say the word and I'll do that instead of step 4.

## Technical notes

- No database migration needed unless you pick the edge-function alternative above.
- `src/lib/mcp/lib/config.ts` and `supabase/functions/_shared/config.ts` keep their own `DEMO_EMAIL` reads from the Deno/process env; their literal fallback is removed too so a misconfigured deploy fails closed (demo writes blocked) rather than open.
